### GPT 主机执行边界

- 先用 Remote Desktop Commander 确认在线 Windows 主机和绝对路径。在 Windows 上定位用户指定的插件目录或 DSH 已安装的 `ts8xxx-dev-plugin`，核对 VERSION、package.json 和 workflow.manifest.json 的版本与当前插件一致。多个路径或设备无法唯一定位、连接不可用、版本不一致时暂停相关操作。下文的脚本路径以该 Windows 插件根为准。编译、烧录、OTA、串口/RTT 和 PPK2 均在 Windows 上调用同一套既有脚本。先读该机上的对应 SKILL.md 和脚本参数。
- 开发和审核先采用只读检查。只有当前任务明确授权修改指定工程才写入；SDK 始终只读。安装与验收仅可读插件文件和使用无工程的只读检查。
- 客户源码、固件、完整日志、设备标识和凭证留在 Windows。使用本机命令计算检查结果，只返回脱敏的摘要。禁止把客户材料传入对话、插件包、外部服务或 GitHub。
- JLink 烧录/擦除、UART 下载、OTA、改变供电/复位以及可能回写设备的测试，均须当前任务有明确授权。执行前核验受控 DUT 的唯一标识、操作方式、固件绝对路径及 SHA-256，并核对构建或交付证据。身份、产物或授权有歧义时暂停。禁用任何可能自动选择其他设备、自动切换端口或附带烧录的回退。无法验证硬件时记录待验证。
- 包内附带流程与规范快照可在离线时阅读。Windows 执行仍需已连接设备。对于嵌入的原始正文，以本节的 GPT 主机边界为先。
