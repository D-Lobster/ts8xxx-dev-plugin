# TS800X 最终审查清单

> 规则全文以 `CODING_STANDARD.md`（R01-R29 + 架构原则）为准；本清单只列核查点。

## 1. 范围与证据

- [ ] 需求、目标工程、改动范围明确；`git diff` 与授权一致，无意外文件。
- [ ] build 0 Error / 0 Warning，固件产物新鲜且非空。
- [ ] 代码质量、依赖报告、硬件项可追溯；"已验证"均有日志/校验/人工确认，否则标"待硬件验证"。
- [ ] 缺陷→回归闭环：`[待硬件验证]` 项在硬件到位后回填复测；回归脚本按项目临时编写，记录复现条件与结果。

## 2. R01-R29 核查

每条单独记录 rule_id、status（PASS/FAIL/N/A/NOT_CHECKED）、文件行号、证据、方法、例外及理由。N/A 必须有适用性依据；NOT_CHECKED 不得冒充 PASS。硬件证据单列。

- [ ] R01 文件头：新建文件记录真实的 @file/@author/@brief/@date；Daniel 仅在确为作者或项目明确指定时使用；其他情况使用真实作者或已确认的组织名，未知时询问，不捏造。
- [ ] R02 函数说明：公共与非显然函数记录 brief，并按需记录 param/retval/note；注释与实现一致。
- [ ] R03 全局变量：应用全局变量使用 `g_`。
- [ ] R04 静态变量：文件静态变量使用 `s_`。
- [ ] R05 局部/函数：`lower_snake_case`，SDK/协议 ABI 例外。
- [ ] R06 宏/常量：`UPPER_SNAKE_CASE`。
- [ ] R07 条件函数：优先 `is_/has_/can_`。
- [ ] R08 大括号：新增及实质修改的 C 代码采用 Allman（左大括号独占一行）；if/else/for/while 即使单句也使用大括号。不批量重排未修改历史代码；已有更严格项目约定的冲突须记录并确认。
- [ ] R09 缩进：4 空格，无 Tab。
- [ ] R10 行宽：≤100 字符；不可分割内容需说明。
- [ ] R11 空格：运算符两侧、逗号后留空格。
- [ ] R12 ISR 日志：ISR 禁止 LOG/printf。
- [ ] R13 ISR 工作量：只做清中断、必要寄存器、固定上限入队/置位；禁止等待和复杂计算。
- [ ] R14 ISR Flash：ISR 禁止 Flash 擦写。
- [ ] R15 阻塞：业务流程禁止阻塞延时；有数据手册依据的短硬件时序需有界并说明。
- [ ] R16 内存：禁止动态分配，使用静态或编译期有界存储。
- [ ] R17 错误处理：校验指针/长度/范围/返回值；错误路径有状态、清理和超时。
- [ ] R18 模块接口：暴露最小且符合实际调度的 init/周期/事件接口，不造空接口。
- [ ] R19 include：自身→应用→SDK/系统，组内稳定排序，不依赖传递 include。
- [ ] R20 GPIO：板级映射集中定义，业务逻辑不散落裸引脚；引脚功能必须符合芯片能力——GPIO2 没有 PWM 复用通道，禁止配置为 PWM 输出（会导致系统复位，FAQ 2.8 Q8）。
- [ ] R21 错误码：多原因使用类型化错误码，纯成功/失败可用 bool。
- [ ] R22 多速率：从统一时基派生，避免模块各自漂移计时。
- [ ] R23 Flash：遵守当前 SDK 的地址/对齐/临界区/上下文要求，API 必须本地核验。
- [ ] R24 复杂度：函数通常 ≤50 非空非纯注释代码行、应用调用深度通常 ≤3（根函数计为第 1 层；SDK 内部不计）；分发可 ≤80 且分支 ≤10；删除无语义包装。
- [ ] R25 移植：保留来源并逐行 diff；时序/协议/索引/引脚差异逐项解释。
- [ ] R26 LOG：设备 LOG 字符串使用可打印 ASCII。
- [ ] R27 BLE 存活检测：所有启用 BLE 的应用必须内置 BBTIME 存活检测：主循环周期比对基带定时器，在 BLE 基带应运行的有效采样期间连续 N 次无变化判定协议栈卡死，LOG 后复位恢复。禁止放 ISR；必须在 `tsBle_Init()` 之后；阈值与复位地址集中宏定义；复位前等待有界并说明依据。
- [ ] R28 RAM 24K 配置：编译后 RAM 占用超过 16K（`0x4000`，越过 `0x20004000`）时，必须启用 `TS_RAM_SAVE_24K`；系统默认休眠只保留 16K，超出部分休眠后丢失会导致异常。每次编译后须记录 RAM 占用数值。
- [ ] R29 编译优化：所有项目（SDK 1.5 / 1.5.1 / 1.6）Target 优化等级固定 **-O1**（`<Optim>1</Optim>`），不得保留按文件的优化等级覆盖；ISR 与主循环共享变量必须 `volatile`；改配置后须全量 Rebuild 并核对 `.dep` 实际 `-O` 标志。

## 3. 架构与系统风险

- [ ] tick 调度函数只做分发（门控 + `xxx_process()` 调用），不堆业务。
- [ ] 状态机覆盖正常/超时/断连/重入/恢复/默认分支；数组/CRC/字节序/转换有边界。
- [ ] ISR/回调/主循环间的所有者、`volatile`、临界区正确。
- [ ] SDK 只读；`.uvprojx` 源文件、include path、配置与代码一致；回归基线已执行或标待验证。

## 4. 烧录与硬件（仅适用时）

- [ ] 固件布局来自工程/HEX，非猜测地址；写入工具完成范围校验和 verify。
- [ ] JLink verify PASS；日志后端按配置，无未允许 ERROR/WARN。
- [ ] BLE/UART/视觉/按键验收记录设备身份、条件、结果。

## 结论

`PASS`（无阻断、证据完整）/ `PASS_WITH_PENDING_HARDWARE`（软件证据完整、硬件项待测）/
`FAIL`（存在问题）/ `BLOCKED`（缺关键证据）。待硬件项不得转换成 `PASS`。
