# TS800X 最终审查清单

> 规则全文以 `CODING_STANDARD.md`（R01-R29 + 架构原则）为准；本清单只列核查点。

## 1. 范围与证据

- [ ] 需求、目标工程、改动范围明确；`git diff` 与授权一致，无意外文件。
- [ ] build 0 Error / 0 Warning，固件产物新鲜且非空。
- [ ] 代码质量、依赖报告、硬件项可追溯；"已验证"均有日志/校验/人工确认，否则标"待硬件验证"。
- [ ] 缺陷→回归闭环：`[待硬件验证]` 项在硬件到位后回填复测；回归脚本按项目临时编写，记录复现条件与结果。

## 2. R01-R29 核查

- [ ] R01-R02：文件头/函数说明真实，无空模板或过期注释。
- [ ] R03-R11：命名前缀、格式、include 顺序、行宽。
- [ ] R12-R14：ISR 无日志/等待/复杂计算/Flash；共享状态原子性。
- [ ] R15-R16：无业务阻塞延时、动态分配、无界资源。
- [ ] R17-R22：指针/范围/返回值校验；接口最小；GPIO 集中且引脚能力已核对
      （**GPIO2 禁止用作 PWM 输出，会导致系统复位**，FAQ 2.8 Q8）；错误码清晰；时基统一。
- [ ] R23-R26：Flash 遵 SDK；R24 例外有据；移植逐行 diff；LOG 仅 ASCII。
- [ ] R27：启用 BLE 的工程已内置 BBTIME 存活检测——主循环调用（非 ISR）、在
      `tsBle_Init()` 之后、阈值与复位地址已宏化、复位前等待有界且有依据；
      无 BLE 时明确标注不适用。
- [ ] R28：本次 RAM 占用（`RW-data + ZI-data`）已记录；超过 16K 时 `cfg_def_app.h`
      已启用 `TS_RAM_SAVE_24K`；未超过时保持默认。
- [ ] R29：Target `<Optim>` = 1（-O1），无按文件优化等级覆盖；
      ISR 与主循环共享变量均为 `volatile`；已全量 Rebuild 且 `.dep` 实测 `-O` 标志
      与配置一致（无漂移）。

## 3. 架构与系统风险

- [ ] tick 调度函数只做分发（门控 + `xxx_process()` 调用），不堆业务。
- [ ] 状态机覆盖正常/超时/断连/重入/恢复/默认分支；数组/CRC/字节序/转换有边界。
- [ ] ISR/回调/主循环间的所有者、`volatile`、临界区正确。
- [ ] SDK 只读；`.uvprojx` 源文件、include path、配置与代码一致；回归基线已执行或标待验证。

## 4. 烧录与硬件（仅适用时）

- [ ] 固件布局来自工程/HEX，非猜测地址；写入工具完成范围校验和 verify。
- [ ] JLink verify PASS；日志后端按配置，无未允许 ERROR/WARN。
- [ ] BLE/UART/视觉/按键验收记录设备身份、条件、结果。

## 结论

`PASS`（无阻断、证据完整）/ `PASS_WITH_PENDING_HARDWARE`（软件证据完整、硬件项待测）/
`FAIL`（存在问题）/ `BLOCKED`（缺关键证据）。待硬件项不得转换成 `PASS`。
