# TS800X 静态分析

在 build 0/0 之外做静态质量闸门：复杂度、可疑代码、MISRA 合规。**编译告警清零归
`ts800x-build`，本技能不重复**；本技能聚焦 lint/复杂度/规范合规。

## 工具现实

- Keil MDK 环境可能没有独立静态分析器。**若配置了** clang-tidy / cppcheck / PC-lint 等，
  优先跑工具并落盘原始输出；**若未配置**，降级为规则审查，并明确标注「工具未配置，仅规则审查」，
  不得写「MISRA 通过」。
- 不为跑工具而要求新装工具；用现有工具，缺工具时走规则审查。

## 检查项

1. 复杂度：函数行数 ≤50（分发 ≤80）、应用调用深度 ≤3、圈复杂度阈值（如 >10 提示、>20 阻断，
   与 R24 对齐）。
2. 未使用变量/参数、未初始化使用、可疑表达式（`=` vs `==`）、无返回值分支。
3. MISRA-C 常用强制项（如适用）：禁止隐式类型降级、有符号/无符号混用、魔法数字、`goto`、
   变长数组、动态内存（对齐 R16）。
4. 指针/数组边界、整数溢出、`volatile` 缺失的共享变量（对齐 R12-R14、R17）。
5. 白名单项：硬件时序、ISR、协议帧、状态分发、已核验 SDK 序列（对齐 R24 例外）——记录理由，
   不机械改写。
6. 引脚能力/外设冲突（阻断项）：
   - **GPIO2 禁止用作 PWM 输出**——GPIO2 没有 PWM 复用通道，配置为 PWM 会导致
     **系统复位**（FAQ 2.8 Q8）。在 `APP/` 中检索 `GPIO2` 与 PWM/定时器配置共现即判违规：
     `grep -nE "GPIO2" APP/ | grep -iE "pwm|timer|Set_Func.*7"`（命中后人工确认语义）。
   - GPIO0/GPIO1（SWCLK/SWDIO）被改作 GPIO/PWM 时，确认 SWD 调试已确认放弃。

## 流程

1. 确认目标文件/模块与范围（新改动优先，全量可选）。
2. 有工具 → 跑工具，收集并过滤误报；无工具 → 规则审查。
3. 逐项给出 `file:line`、严重度、证据、建议，白名单项记理由。
4. 需要改的项经用户确认后修改，再 build 0/0 + 依赖分析（不替代硬件验证）。

## 严格规则（违反即失败/标注）

- 静态分析是辅助闸门，不替代 build 0/0 和硬件/物理验证。
- 不因 MISRA/复杂度指标机械改写时序、ISR、协议帧、状态机（R24 例外）。
- 未配置工具时结论只能写「规则审查通过/需人工复核」，不得写「MISRA 通过」「无静态告警」。

## 输出

写入 `context/handoffs/<module>/static_analysis.json`：工具及版本（或「未配置」）、扫描范围、
发现项（严重度/file:line/证据）、白名单及理由、是否已修、build 结果、next_action。
