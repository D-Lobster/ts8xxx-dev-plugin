# TS800X 编码规范 R01-R29

本 Skill 是 `RULES/CODING_STANDARD.md` 的宿主可携带镜像。所有规则针对应用代码；目标 SDK 保持只读。先遵循目标项目已有且更严格的约定，冲突时报告，不静默改写。

## 规则

| 编号 | 要求 |
|---|---|
| R01 | 新建文件包含真实的 `@file @author @brief @date`；不知道作者时询问或使用项目既有组织名，不捏造个人。 |
| R02 | 公共接口和非显然函数写 `@brief`，按需写 `@param/@retval/@note`；注释必须与实现一致。 |
| R03 | 应用全局变量用 `g_` 前缀。 |
| R04 | 文件静态变量用 `s_` 前缀。 |
| R05 | 局部变量和函数使用 `lower_snake_case`，除非必须匹配 SDK/协议 ABI。 |
| R06 | 宏和编译期常量使用 `UPPER_SNAKE_CASE`。 |
| R07 | 返回布尔条件的函数优先使用 `is_/has_/can_`。 |
| R08 | 使用 K&R 大括号。 |
| R09 | 4 空格缩进，不使用 Tab。 |
| R10 | 代码行不超过 100 字符；不可分割的 URL/生成内容需说明。 |
| R11 | 运算符两侧和逗号后留空格。 |
| R12 | ISR 禁止 LOG/printf。 |
| R13 | ISR 只做清中断、必要寄存器访问、固定上限入队/置位；禁止等待、无界循环和复杂计算。 |
| R14 | ISR 禁止 Flash 擦写。 |
| R15 | 运行时业务流程禁止阻塞延时；使用事件、计数器或状态机。硬件数据手册要求的短时序仅在有依据且有界时例外。 |
| R16 | 禁止 `malloc/calloc/realloc/free`；使用静态或编译期有界存储。 |
| R17 | 校验指针、长度、范围和返回值；错误路径有明确状态、清理和超时。 |
| R18 | 模块暴露最小接口；按实际调度提供 `_init`、周期处理或事件入口，不强制无意义的空接口。 |
| R19 | include 顺序为自身头、应用头、SDK/系统头；组内稳定排序，避免依赖传递 include。 |
| R20 | 板级 GPIO 映射集中定义，业务逻辑不散落裸引脚号；GPIO2 不支持 PWM，禁止用作 PWM 输出（会导致系统复位，FAQ 2.8 Q8）。 |
| R21 | 多种失败原因使用类型化错误码；纯成功/失败可用 `bool`。 |
| R22 | 从统一时基派生多速率任务，避免各模块重复且漂移的节拍。 |
| R23 | Flash 操作遵守当前 SDK 的地址、对齐、临界区和执行上下文要求；所用临界区 API 必须从本地 SDK 核验。 |
| R24 | 函数通常 ≤50 代码行、应用调用深度通常 ≤3；调度/分发可 ≤80 且分支 ≤10；去除无语义单调用者包装和过度抽象。 |
| R25 | 移植代码必须保留源文件并逐行 diff；时序、协议、索引和引脚差异逐项解释，不能凭记忆重写。 |
| R26 | 设备 LOG 字符串只用可打印 ASCII；用户文档和源码注释可用中文。 |
| R27 | 所有启用 BLE 的应用必须内置 BBTIME 存活检测：主循环周期比对基带定时器，连续 N 次无变化判定协议栈卡死，LOG 后复位恢复。禁止放 ISR；必须在 `tsBle_Init()` 之后；阈值与复位地址集中宏定义；复位前等待有界并说明依据。BLE 模块缺失该功能视为未完成。 |
| R28 | 编译后 RAM 占用超过 16K（`0x4000`，越过 `0x20004000`）时，必须在 `cfg_def_app.h` 启用 `TS_RAM_SAVE_24K`；系统默认休眠只保留 16K，超出部分休眠后丢失会导致异常。每次编译后须记录 RAM 占用数值。 |
| R29 | 所有项目（SDK 1.5 / 1.5.1 / 1.6）Target 优化等级固定 **-O1**（`<Optim>1</Optim>`），不得保留按文件的优化等级覆盖；ISR 与主循环共享变量必须 `volatile`；改配置后须全量 Rebuild 并核对 `.dep` 实际 `-O` 标志。 |

## R27 BLE 存活检测（强制）

环境干扰（强电磁场、电源纹波、ESD）可能导致 BLE 基带定时器停振、协议栈卡死；主循环仍在
运行时通用看门狗无法覆盖。所有启用 BLE 的应用（从机/主机/多角色，含 2.4G 共存）必须内置：

1. 主循环调用（`tsBle_Loop()` 之后），禁止放 ISR（R12/R13）。
2. 周期读取 `GET_CUR_TICK_US()` 并与上次值比对；连续 N 次（默认 30）无变化 → LOG + 系统复位。
3. 必须在 `tsBle_Init()` 之后调用，否则定时器未运行会误判。
4. 阈值、复位寄存器地址/写入值集中宏定义（R06/R20），禁止魔法数字。
5. 复位前日志等待必须有界并注明依据（R15 例外）；静态变量用 `s_`（R04）。
6. 模块验证须覆盖触发路径，真机无法触发时记录 `[待硬件验证]` 及测试步骤。

完整规则与参考实现见 `RULES/CODING_STANDARD.md` 的 R27；原始问答见
`ts800x-faq` 技能 `references/TS800X-FAQ.md` 2.11 Q6。符号名称以本地 SDK 核验为准。

## R28 RAM 容量配置（16K / 24K，编译后检查）

片上 RAM 共 24K（`0x20000000`–`0x20006000`），**16K 边界为 `0x20004000`**。系统默认休眠
只保留前 16K（`system.c`：`AON_CTRL->AON_CTRL0 = 0x7A`）；只有定义 `TS_RAM_SAVE_24K`
时才写 `0xFA`，即 24K 全保留。

**要求**：

1. **每次编译后检查 RAM 占用**：Keil 构建输出 `Program Size` 的 `RW-data + ZI-data`
   （或 map 中 RAM 段最高地址）。
2. 超过 16K 时，必须在 `APP/include/cfg_def_app.h` 加入 `#define TS_RAM_SAVE_24K`；
   未超过则保持默认。
3. 不开而超限 → 休眠后高地址数据丢失，唤醒异常（变量被破坏、状态机错乱、HardFault）。
4. 编译证据必须记录该次 RAM 占用数值；改动需写入模块报告与 `PROGRESS.md`。

完整规则见 `RULES/CODING_STANDARD.md` 的 R28。

## R29 编译优化等级（-O1）与共享变量可见性

**所有**项目（不论 SDK 1.5 / 1.5.1 / 1.6）的 Target 优化等级固定 **-O1**
（`.uvprojx` 中 `<Optim>1</Optim>`）——这是项目自定义的强制约束，SDK 未声明。
等级错误（尤其 -O0 或"配置写 -O1、实编 -O0"漂移）会导致时序与任务调度异常。

1. 不得使用 -O0 / -O2 / -O3，也不得保留或新增按文件的优化等级覆盖。
2. **ISR 与主循环共享的变量必须 `volatile`**（含 `extern` 声明）：否则 -O1 下主循环
   的标志读取会被优化成寄存器缓存或常量折叠，周期任务停摆。样板：`body-scale`。
3. 改配置后必须**全量 Rebuild**，核对新 `.dep` 的 `-O` 标志与目标一致。

完整规则见 `RULES/CODING_STANDARD.md` 的 R29。

## R24 例外

硬件时序、ISR、协议帧、状态分发和已核验 SDK 调用序列不因行数指标机械改写。例外必须说明原因、边界与验证方式，不能成为隐藏过度设计的借口。

## 执行检查点

- 编码前：列出应用层调用链、状态所有者和 ISR 边界。
- 编码后：在报告中记录最长函数、最深应用调用链和例外；不要向每个函数写 R24 计数注释。
- 模块初编译后：执行 `ts800x-code-quality`，再编译确认。
- 最终交付：结合 build、diff、依赖报告和 `ts800x-final-reviewer` 逐条核对 R01-R29。
